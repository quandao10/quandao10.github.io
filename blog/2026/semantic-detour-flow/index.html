A short walk through the method and the results — 1 min 21 s, with sound.

Diffusion models trained in semantic latent spaces converge much faster than pixel-space models, but they inherit a decoder that caps fine detail. Semantic Detour Flow closes most of that gap without any decoder: it is a pixel-space flow that follows frozen DINOv2 features1 at high noise and hands over to pixels at low noise. One network, one velocity loss, and sampling that runs entirely in pixel space.

Why pixel diffusion is slow

The gap is in the denoising target at high noise. When almost everything is noise, the best a model can do is predict the posterior mean of the target given the noisy state. For pixels, that posterior mean is a blur — an average over everything the image could have been. For self-supervised features it is a semantic prototype: a representation that still says what the thing is.

So a pixel model spends its early training budget learning to produce blur, while a latent model spends the same budget learning content. That is the asymmetry, and it is the one thing worth fixing.

The detour

Let \(c(x)\) be the frozen DINOv2-B features of \(x\) on the 16×16 patch grid, centred and scaled to standard deviation 0.5 — the scale of the image itself, so neither term dominates. We call it the code. Let \(\Phi\) be the pixel shuffle that maps each 768-dimensional token into the 3×16×16 pixels of its patch, so \(\Phi c(x)\) is image-shaped and aligned with \(x\).

The noisy state mixes the image and the code, then adds noise:

\[z_t = t\,m_t + (1-t)\,\varepsilon, \qquad m_t = \alpha_t\,x + \beta_t\,\Phi c(x).\]

The weights hand the signal over from the code at \(t=0\) to the image at \(t=1\). We use a trigonometric hand-over with a mid-path norm bump:

\[(\alpha_t, \beta_t) = g_t\,(\sin\theta_t,\, \cos\theta_t), \qquad \theta_t = \tfrac{\pi t}{2}, \qquad g_t = 1 + \kappa \sin 2\theta_t,\]

with \(\kappa = 0.25\). Plain pixel flow is the special case \(\alpha \equiv 1\), \(\beta \equiv 0\). Differentiating gives the target velocity, and a single network is trained against it with one unified loss — predicting pixels and code together.

DINOv2-B’s 768 channels are exactly one 16×16×3 patch, so \(\Phi\) is an isometry onto the image. That coincidence is convenient, not essential; other encoders and code widths work too.

Watch the hand-over

The video runs the equation above continuously in \(t\), on a real image with its real code (shown by its first three principal components). On the left is the signal \(m_t\) the path points at; on the right the state \(z_t\) the network actually sees. Near noise the signal is a semantic prototype; near data it is the photograph.

Sampling needs none of this machinery. It integrates a pixel-space ODE from noise to data — no encoder, no decoder, nothing to reconstruct through.

ImageNet

At 256×256, Detour-XL/16 reaches FID-50k 1.43 in 200 epochs; at 512×512, Detour-XL/32 reaches 1.59 in 160 epochs. Without guidance the same models reach 3.69 and 4.19.

Both runs were continued, and both now reach 1.35: 256×256 gets 1.35 at epoch 320, and 512×512 gets 1.35 at epoch 280. At 512 most of that came from the guidance window rather than from the extra epochs — the same setting on [0.05, 0.75] measures 1.46 on two separate runs, and widening to [0.05, 0.9], the value 256 already used, gives 1.35. Epoch 320 at 512 is worse than 280, so the longer run is not uniformly better.

Guidance matters, and the two kinds compose. Classifier-free guidance2 alone plateaus; autoguidance3 alone is already better at a much lower Inception score; together they are better than either. CFG contrasts the conditional velocity against the unconditional one, \(v_c - v_u\); AutoGuidance contrasts it against the same model earlier in training, \(v_c - v_g\), using the epoch-20 checkpoint as \(v_g\) so it needs no extra training. The two directions are nearly orthogonal (\(\cos \approx 0.2\)), so they add:

\[v \;=\; v_u \;+\; s\,(v_c - v_u) \;+\; (a-1)\,(v_c - v_g), \qquad t \in [0.05,\, 0.9],\]

with \(v = v_c\) outside that window. The split of labour is clean: CFG picks the class near noise, where the class is still undecided, and AutoGuidance improves quality along the rest of the path. That is also why the window matters — the CFG term goes to zero once the code reveals the class, so running it over the whole path only costs compute.

Text to image

The path needs no class labels, so it transfers to text-to-image directly. With matched networks it reaches comparable text alignment in 1.5× fewer training iterations than plain pixel flow.

A 3.3B model scores GenEval 0.90 / DPG-Bench 87.8 at 512×512 and 0.88 / 87.4 at 1024×1024 — ahead of the pixel-space models we compare against at both resolutions, while keeping the fine textures and rendered text that a semantic-latent decoder can lose.

Vision encoder and code dimension

The default code is DINOv2-B with 768 channels, chosen because that is exactly a 16×16×3 pixel patch: the pixel shuffle \(\Phi\) maps the code into an RGB-shaped state without changing its dimension or its norm. Two questions follow — what happens when the code dimension does not match, and does the choice of encoder matter at all? All runs below are JiT-B/16 on ImageNet 256 for 80 epochs, unguided, with the same sampler: relative comparisons, not best achievable numbers.

Encoder Adaptation C State R2 FID-50k
DINOv2-B – 768 3 – 16.85
DINOv2-L project 768 3 0.682 15.01
DINOv2-L pad 1024 4 – 17.39
Other encoders, same 768-channel interface
MAE33 – 768 3 0.916 22.77
LeJEPA34 – 768 3 0.793 23.05

R2 is linear patch reconstruction from the code token, estimated from 1.03M tokens.

Projecting beats padding. DINOv2-L has 1024 channels, which pixel shuffle turns into a four-channel state — and the fourth channel has no clean image behind it, only code. Projecting down to 768 instead keeps the three-channel state and the unmodified pixel-space architecture, and wins by 2.4 FID-50k (15.01 against 17.39) while retaining 94.7% of the feature variance. The projection is PCA followed by a fixed orthogonal rotation, which balances the channel variances so that pixel shuffle spreads them evenly across the three RGB planes rather than concentrating them in one. Keeping the state shaped like an image matters more than keeping every direction of the feature.

The encoder is not interchangeable. Swapping DINOv2 for MAE or LeJEPA at the same 768 channels and the same architecture costs about 8 FID-50k, and both alternatives converge more slowly throughout training (figure, right — they are still at 26.0 FID-10k at epoch 80, where DINOv2 is at 18.1).

The obvious explanation does not survive. Pixel predictability — how well a linear ridge regressor reconstructs a patch from its code — is highest for MAE (\(R^2\) 0.916, against 0.682 for projected DINOv2-L), and MAE generates worst. Easier reconstruction does not mean easier generation. What separates the encoders is the semantic structure of the representation itself, which is the thing the detour path actually travels along.

Code feedback

The sampler already predicts a code at every step, and then throws it away. Feeding it back — in the manner of self-conditioning35 — costs almost nothing and is the single largest unguided gain we found.

A zero-initialised linear layer projects the previous step’s predicted code to the trunk width and adds it to the input patch tokens; the first step gets zeros. Training needs a gradient-free first pass to produce the feedback for half of each batch, about 25% more training time. Sampling needs no extra network evaluations at all, since the previous prediction is already in hand. Under CFG the conditional and unconditional branches keep separate feedback codes.

At base scale feedback halves FID-10k — 38.2 to 18.6 at 20 epochs, 18.4 to 7.98 at 80. It helps plain pixel flow too, but the detour path still wins under the same mechanism (21.6 against 47.9 at 20 epochs), so the gain is not simply self-conditioning wearing a different hat.

It scales. At XL, feedback roughly halves FID-10k at epoch 20 (16.5 → 8.36), and by epoch 40 it has already passed the 200-epoch model without feedback (6.40 against 6.86). Unguided FID-50k at epoch 80 goes from 5.34 to 3.18.

Architecture, briefly

A 32-pixel encoder lays out the image and passes its tokens to a 16-pixel decoder that predicts image and code together. The loss is a single velocity objective against targets \(x\) and \(c(x)\), with DINOv2 frozen throughout — it is used to define the path, never trained.
